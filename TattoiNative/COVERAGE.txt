- Direct reschedule and two-step preview/send of changed-promotion terms; client accept/decline and artist withdrawal through the same backend.
- Finish-session/final-payment-request flow; zero-remaining completion uses the existing appointment action. These actions were not executed in testing.
- Client profile/history, scoped private notes and form-status visibility.
- Client consent review, medical answers and PencilKit signature submission. Not signed during testing.
- Campaign create/edit, image upload, percentage/fixed discounts, paid/complimentary vouchers, selected sitting months, limited availability, expiry, issue to one client, audiences/manual selection/presets/birthday/city filters, SMS/push channel options subject to server capability, and archive.

- Profile/photo/location/business editing, services and weekday hours. Unknown saved service/day properties survive edits.

NOT YET A COMPLETE NATIVE PORT
- Native Stripe payment checkout for client deposits/balances, voucher purchases and supplier purchases. Existing APIs return a mix of PaymentIntent and embedded Checkout session secrets; an appropriate native checkout contract/SDK must be completed and tested, not treated as interchangeable.
- APNs notification delivery, device-token registration, user-bound token lifecycle, background/deep-link notification routing. Web Push subscriptions do not work as native push. Requires Apple team/capability and backend delivery work.
- Push and SMS delivery tests, physical-device lifecycle/offline recovery, automatic browser-to-native return links.
- Native supplier and master-developer account roles.
- Client Discover/feed/reels and complete client portal parity.
- Complete Stripe verification-document upload, native account registration/recovery/deletion and policy screens required for release.
- Studio/team management, storefront/event management, purchases/refunds, billing/subscriptions, waitlist and all secondary business operations.
- Advanced schedule breaks/time-off/travel editors, service mapping, full portfolio editing/classification, aftercare editing and procedure-record detail/export.
- Complete voucher acceptance/use/transfer, pinned promotion consultation UI, rich media/video/structured-message parity, older-message pagination and thread attachments beyond direct image messages.
- End-to-end authenticated tests of every implemented native mutation; no production scale/security/App Store sign-off is implied by compiler success or six core tests.

WHY THIS LIST EXISTS
A native conversion is a frontend rewrite. The existing backend is reused, but browser components cannot simply become SwiftUI. This branch provides a real compiling and launched native implementation, with unsupported flows clearly identified. It must not be described as a finished replacement for the PWA.
