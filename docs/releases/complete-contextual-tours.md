# Contextual tours: implementation and verification

Status: implemented and locally verified. Delivery branch: codex/tattoi-ivory-design-system.

## Behavior

Every V3 screen, shared feature sheet and dialog has a question-mark entry point. Discover, artist profiles, booking requests, the artist map and artwork lightbox have matching entry points. Guided walkthrough links open their destination and start its live tour.

The island highlights the current component and moves with it. It offers Back, Next, Skip, Done and minimise/expand. Opening a tab, disclosure or nested feature updates the guide to the visible controls. State-dependent explanations update without moving the user to a different step. Tour navigation does not activate business actions.

The guide uses the existing Ivory tokens, viewport/safe-area bounds and reduced-motion styles. Dialog tours remain within the owning portalled dialog so keyboard focus is retained. Escape dismisses the guide without dismissing the underlying feature, and focus returns to its trigger.

## Validation scope

Browser checks use intercepted fixture responses and do not send real messages, submit live imports, charge cards or remove records. Payment and identity fields hosted by Stripe are treated as a secure provider panel; provider component tests use mocks. Browser fallback/confirmation checks do not certify live Stripe account verification or settlement. These are tour changes, not changes to transaction authorization.

Full unit suite: 314 tests across 75 files passed. Existing message, scrolling, calendar and sitting regressions passed. Native asset parity passed. The combined release gate passed 86 role-route cases, 16 public/authentication cases, 93 feature cases and three interaction sizes.
